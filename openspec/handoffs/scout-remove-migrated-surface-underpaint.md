## Current draw and geometry contract

`src/app/shell_run.rs` has three draw sites. The first two call `self.app.render(f)` only; the steady-state site calls `self.app.render(f)`, then resize pushes, then the mounted component views in this order: playback, Home, Feeds, ABS podcast, ABS book, Emby browser, TV workspace, Music workspace, inline search, queue, and overlay stack.

`App::render` in `src/app/render/screens/root.rs` is currently both the geometry pass and the legacy painter. It creates a fresh `AppLayout`, normalizes the destination, computes the main/right/left areas, invokes `render_main`, tags `browse_destination`, and atomically swaps `self.layout`. `render_main` paints the shared chrome and delegates the body through `render_library`/`render_list`. The atomic swap and zero-area early return are load-bearing and must survive D2.

## Layout producers/readers that must survive paint extraction

`AppLayout::playback`: `player_area`, `status_area`, seek/indicator/button rects and idle-feed link are produced by chrome/player/status paths and consumed by input, playback shell/component adapters, and status handling.

`AppLayout::main`: `panel_area`, `panel_content_area`, `left_area`, queue areas/maps, selector/breadcrumb data, selected rects, `home_area`, `feeds_area`, `hero_area`, `inline_hero_area`, `wide_music_*`, `movies_wide_*`, `tv_wide_*`, and ABS book/podcast areas are consumed by shell component adapters, input/hit testing, overlay anchoring, and persistence. Every fresh frame must reset these fields through `AppLayout::default()` and atomically install the completed layout.

`tabs_area` is used for tab hit geometry. `browse_destination` must continue to be tagged only after the normalized destination's complete layout is assembled.
