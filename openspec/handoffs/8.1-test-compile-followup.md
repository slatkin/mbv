## Root cause of the new regression

The 8.1 production fix added `pub(super) fn tuirealm_key_to_crossterm` in
`src/app/input_resolver.rs` to bridge `tuirealm::event::KeyEvent` →
`crossterm::event::KeyEvent` for the central router. The function mapped
named TuiRealm keys (Backspace, Enter, Tab, Esc, Function, …) and a
wildcard arm, but **had no arm for `TuiKey::Char(c)`**. Every character
keypress fell through the wildcard to `KeyCode::Null`.

The router consequently saw `Null` for every typed key, which broke
`playback_command_for_key` (returns `None` for `Null`), broke
`update_double_tap_state`'s `(KeyCode::Char(' '), …)` arms, and made the
double-tap timer never arm. Space-to-toggle and every other character
binding silently stopped working in the router path.

The space-press test caught it because it is the only test that drives a
character key through `router_outcome` and then asserts on the App-owned
`last_space_press` timestamp.

## Fix

Single-line change in `src/app/input_resolver.rs` (add the missing arm
**first** so subsequent `Backspace`/`Char` arms remain stable):

```rust
TuiKey::Backspace => crossterm::event::KeyCode::Backspace,
TuiKey::Char(c) => crossterm::event::KeyCode::Char(c),   // <-- added
TuiKey::Enter => crossterm::event::KeyCode::Enter,
```

| --- | --- | --- |
| `shell::tests::router_records_first_space_for_second_claim` | FAIL | PASS |
| `shell::tests::router_records_first_esc_for_second_claim` | PASS | PASS |
| `shell::tests::ui_root_router_command_opens_help` | PASS | PASS |
| `shell::tests::converted_surface_skips_observer_key_but_retains_redraw_signal` | PASS | PASS |

| `shell::tests::terminal_focus_observer_preserves_refocus_side_effects` | PASS | PASS |

Full suite is now **1088 passed, 4 failed** — the exact 4 named in the
baseline. No new regressions from this fix.

## Why a one-line gap had this blast radius

`tuirealm_key_to_crossterm` is the only path by which character keys
reach the central router. The legacy `App::handle_key` path was deleted
in 8.1, so the converter is no longer one of several fallbacks — it is
the only path. A missing arm therefore affects every character binding
in the app, not just space.

`esc_double_tap` worked by accident: `Key::Esc` is a named arm, so
`Esc` survived the wildcard.

## Why the handoff missed this

The handoff verified compile success (`cargo check -p mbv --tests` is
clean) and reviewed the structural shape of the new converter, but did
**not** exercise the runtime path. The space-press test would have
caught it on any run. The next agent should treat "compile is clean" as
necessary but not sufficient and run the focused test suites for any
newly-added function before declaring production stable.

## Out-of-scope finding (flagged for 8.2 / 9.x, do NOT fix here)

`make check-code-file-lines` fails on `src/app/components/msg.rs` (810
lines, cap 800). 8.1 added 71 net lines to msg.rs (the `QueueIntent`
enum, the `Undo` arm, the `TuiKeyEvent` rename, plus the
`TerminalObserverEvent` expansion) and pushed it over. Per the rule
"Source files cap at 800 lines; split over-limit files in the same PR"
this is a 8.1 follow-up, not a test compile issue. The natural split is
a new `msg/queue.rs` for the queue/scoped intent enums
(`QueueIntent` / `QueueRequest` / `QueueMove` / `QueueColumnResize`) and
a new `msg/overlays.rs` for the hit-region enums
(`BrowserHitRegion` / `HomeHitRegion` / `QueueHitRegion` / `TvHit` /
`TvHitRegion`).
