# Proposal: adr-amendment-hygiene

## Why

A three-scout audit (2026-11-04, main @ `06883d63b`) verified every checkable claim in all 34 ADRs and `CONTEXT.md`: 24 of 34 ADRs carry rotted material, and the worst class is inverted — the documents assert the opposite of the tree. ADR 0019 and `CONTEXT.md` say the daemon "still does NOT admit Audiobookshelf" while `daemon_admits(..., has_audiobookshelf)` ships in `crates/mbv-daemon/src/control_queue.rs` with live `abs-*` ctrl capabilities; ADRs 0014/0015/0017/0018 and `CONTEXT.md` cite "open PR #529", "v7 on main", and "mbvd Emby-gated" for work that merged on 2026-08-14 (`bd92a9157`, protocol now v10). Because ADRs are a fixed source for architecture work, these stale claims actively steer agents and reviews wrong — they did in this session's own analysis. The root cause is structural: every false claim lives in a *status* sentence ("on main now", "open PR", "planned in openspec/changes/", "file.rs:117") inside amendment blocks, and nothing ever re-checks them, because the spec-sync pass reaches specs, never ADRs.

## What Changes

- **One writing rule for ADRs** (recorded where ADR conventions live, e.g. a short preamble in `docs/adr/` or the docs-writing guidance): an ADR states the decision and its rationale, and amendments state decision *changes* only. Amendments never carry `main`-status, never carry open-PR/milestone/issue status, and never carry file:line anchors. Where the world changed, the amendment names the superseding ADR or spec — the synced source of current behavior — not the diff state.
- **One coordinated refresh of the 2026-08-14 status cluster** (ADR 0014, 0015, 0017, 0018, 0019 + `CONTEXT.md` Owner admission § and mbvd §): rewrite each status sentence as a decision statement, delete the merged-PR/open-PR/milestone/version-number prose, and state the current truth only by pointing at the owning spec (`ctrl-protocol`, `daemon-lifecycle`, Owner admission) or code symbol (`CTRL_PROTOCOL_VERSION`, `daemon_admits`).
- **Dead-anchor repair** (mechanical, decision text untouched): repoint or delete `crates/mbv-core/src/{ctrl,daemon/*}` paths (0001, 0006, 0010, 0014, 0015, 0017, 0019 — now `crates/mbv-ctrl/`, `crates/mbv-daemon/`, `crates/mbv-queue/`, `crates/mbv-remote-player/`), `src/app/*` leaf paths moved by the dispatch split (0002, 0010, 0022, 0024), `src/tray.rs` → `crates/mbv-desktop/src/tray.rs` (0004), and prefix the seven unprefixed `openspec/changes/<name>/` refs with their dated `archive/` directory (0017, 0019, 0026, 0028, 0033, 0034). Line-number-only anchors are deleted, not repointed.
- **Futures-that-arrived updates**: ADR 0002's "Roadmap (not scheduled)" keybinds block (shipped, `configurable-keybinds` spec exists); ADR 0022:83 and ADR 0024's Consequences still list Residual B (#643) as open (closed 2026-09-05, `is_wide_*` predicates deleted); ADR 0024's drag/hover note corrected to drag-shipped/hover-pending.
- **Five targeted follow-up verifications as tasks** (verify before writing, not bulk-fix): mbvd ctrl auth (#523) actually landed in #529?; Residual C (page-rows-off-global-geometry) fixed or still open?; `CONTEXT.md`:161 "without change to scope" leftover Queue-scope wording?; did `openspec/changes/adopt-wide-hero/` ever exist (0026:46)?; does `Resolution::Refuse` still mean "bare foreground TUI" after ADR 0030 (0006 amendment vs `src/single_instance.rs:48` doc disagreement)?
- **Out of scope, recommended as its own change**: the ADR 0027 case runs the other way — the ADR and code say hero LEFT, but `canonical-media-lists`, `right-panel-arrangements`, and two `CONTEXT.md` hero sections still describe the superseded 0026 right-pane layout. That is a spec-correction of layout behavior, not doc hygiene; it needs a real spec delta and is proposed as a separate change (e.g. `sync-hero-left-specs`) pending user decision. Also out of scope: the `libmpv2`/`libmpv2-sys` manifest residue (ADR 0032 finding) — a build-hygiene change, not docs.

## Capabilities

Docs-only change: no runtime behavior changes, no spec deltas. `skip_specs: true` is set in `.openspec.yaml`. (The 0027 spec correction, if approved, becomes its own change with its own delta specs.)

## Impact

- Files touched: `docs/adr/0001,0002,0004,0006,0010,0014,0015,0017,0018,0019,0022,0024,0026,0028,0033,0034` plus a convention note; `CONTEXT.md` (Owner admission, mbvd, control-credential, hero sections pending 0027 decision). No code, no specs, no protocol, no build files (libmpv2 residue deferred).
- Risk: low — prose only. The one substantive risk is rewriting an amendment so aggressively that a decision record loses its rationale; mitigated by the rule "amendments state decision changes, delete only status sentences" and by per-file review before commit.
- The audit inventories (per-ADR verdicts, pattern table, five ambiguities) from the 2026-11-04 three-scout audit are recorded in the session reports and summarized in this proposal; they are the worklist for tasks.md.
