## 3. Owner side: registry, admission, swap state machine (`crates/mbv-daemon`)

- [ ] 3.1 Record `Option<SwapSurface>` (`enum SwapSurface { Terminal, Pinned }`) per `CtrlClient` from the Hello capabilities (`ctrl_client_capabilities` in `core_ctrl_spawn.rs`, `CtrlClients::connect*` in `ctrl.rs`). Add registry queries: "the pinned Client" and "the last-connected Client with `Some(Terminal)`", local transport only. Keep an `Arc<AtomicBool>` "pinned Client attached" up to date on connect and disconnect, and expose it on `DaemonPlayerHandle` (design D3). Verify: unit tests in `ctrl.rs`'s test module for the newest-terminal choice (contract: spec "Pin replaces the newest unpinned Client", two-Client scenario) and for the flag clearing when the pinned Client leaves.
- [ ] 3.2 Add the hooks `swap_command` and `notify` to `DaemonRuntimeHooks` (`core.rs`), with `SwapDirection { Pin, Unpin }`. `mbvd` (`crates/mbvd/src/main.rs`) passes an `Err`-returning `swap_command` and a no-op `notify`. Verify: `cargo check -p mbvd -p mbv-daemon`.
- [ ] 3.3 Implement `event_loop/pin_swap.rs` per the design D3 state machine. On `TransportCommand::PinSwap`: pick the direction and target from the registry, resolve `swap_command` (on `Err`, notify and stay `Idle`), send `SwapPrepare` or spawn directly when there is no target. On `SwapPrepared` from the target: set `MBV_SWAP_TOKEN` (uuid v4), spawn, hand the `Child` to a waiter thread that sends `DaemonEvent::PinSwapChildExited { token, success }`. Abandon with a notification on the 10 s deadline (checked in `poll(now)`), a spawn error, `success == false` while `Awaiting`, or the target leaving while `Preparing`. A click while not `Idle` does nothing. Wire `poll` into `event_loop.rs` beside `tray.poll`. Verify: unit tests with injected `now` and a fake `swap_command` (no real process, no sleep), one per contract: the deadline abandons and notifies (spec "New Client never attaches"), a second click is ignored (spec "Second click during a swap"), and an unresolvable command sends no `SwapPrepare` (spec "Neither set").
- [ ] 3.4 Admission exception (design D4): in `send_admission_refusal`, admit a Hello whose `swap_token` matches the pending `Awaiting` token despite `ExclusiveOwner`, consume the token, and then send `SwapQuit` to the target if it is still attached; the machine returns to `Idle`. The shutting-down refusal still wins. Verify: unit tests in `core_ctrl_spawn.rs`'s test module for matching token admitted with Stay-alive off, and for the same token refused on a second use (spec `daemon-lifecycle` "Pin swap with Stay Alive off").
